# Подбор запчастей и аналогов

Клиент для веб-сервиса «Проценка» Favorit-parts: поиск производителей по артикулу и подбор предложений и аналогов по выбранному бренду.

Стек: React 19, Redux Toolkit, Bootstrap 5, Vite, Vitest + Testing Library. Без TypeScript.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты
```

По умолчанию используется тестовый ключ из документации. Свой ключ и демо-режим задаются в `.env` (пример в `.env.example`):

```bash
VITE_API_KEY=ваш-ключ
VITE_USE_MOCKS=true   # ответы из примеров документации, без сети и ключа
```

## Как работает

1. Пользователь вводит артикул. Поиск запускается через 600 мс после окончания ввода или сразу по Enter. Предыдущий незавершённый запрос отменяется.
2. Приходит список производителей. По клику на бренд уходит запрос `number + brand + analogues=on`.
3. Таблица показывает искомую деталь и аналоги: производитель, номер, название, склад, дата отгрузки, остаток и цена. Сначала искомая деталь, затем позиции в наличии по возрастанию цены, затем отсутствующие. На узком экране таблица складывается в карточки.

## Особенности API, которые учтены

- **CORS и http.** API отдаётся по `http://` без CORS-заголовков, поэтому браузер ходит на `/api`, а Vite проксирует запрос на `api.favorit-parts.ru`. В продакшене ту же роль выполнит Nginx или BFF; там же должен жить ключ покупателя, а не в клиентском бандле.
- **Ошибки с кодом 200.** Ошибка приходит полем `error`, известные коды переведены на русский.
- **«Не найдено».** API возвращает массив с одной пустой структурой, она отфильтровывается.
- **Цена.** Корневое поле `price` в документации помечено «не использовать», цена берётся из складов (`warehouses[].price`).
- **Номер детали.** API ищет без учёта разделителей: по запросу `0189` приходит `01-89`. На втором шаге передаётся номер из запроса, номер из ответа только показывается.
- **Спецсимволы** в номере и бренде (`NGK/NTK`, `#`, `&`) экранирует `URLSearchParams`.
- **Невозвратные позиции.** Запрос идёт с `info=on`, признак `notRefund` выводится бейджем.
- **Гонки запросов.** В Redux сохраняется `requestId` последнего запроса, ответы на устаревшие игнорируются.

## Структура

```
src/
  api/
    favoritApi.js      запросы к API и обработка сетевых ошибок
    normalize.js       приведение ответов к виду для интерфейса (чистые функции)
    mock.js            демо-режим на примерах из документации
  store/searchSlice.js состояние двух этапов поиска
  components/          форма, список брендов, таблица, лоадер, ошибки
```

## Тесты

Покрыто то, где реально можно ошибиться:

- разбор ответов API: пустой результат, ошибки, цена со склада, порядок позиций, дата отгрузки без сдвига часового пояса;
- игнорирование устаревших ответов в Redux;
- пользовательский сценарий целиком: ввод артикула → выбор бренда → таблица; «ничего не найдено»; сбой сети и повтор запроса.
